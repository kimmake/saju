# Handoff: 운결 (Ungyeol) — 사주 분석 웹 서비스

## Overview
생년월일·태어난 시간을 입력하면 개인 사주 해석을 보여 주는 한국어 웹 서비스. 흐름: **입력 → 분석 중(로딩) → 결과**. 결과는 요약 헤더 + 사주팔자/오행 요약 + 7개 항목(자녀운, 배우자운, 금전운, 직장운, 어울리는 띠 TOP3, 2027년 띠 TOP3, 공부운)으로 구성된다.

## About the Design Files
이 폴더의 파일은 **HTML로 만든 디자인 레퍼런스(프로토타입)**다. 그대로 배포할 코드가 아니다. 대상 코드베이스의 기존 환경(React/Next.js, Vue 등)과 패턴으로 **다시 구현**한다. 환경이 없다면 Next.js(App Router) + React + Tailwind 또는 CSS Modules를 권장한다.
- `ungyeol.dc.html` — 화면 전체(템플릿 + 로직 클래스). 같은 폴더의 `support.js` 런타임으로 브라우저에서 바로 열린다.
- `saju-data.js` — 데이터 계층(입력 계약, `analyze()` 서비스, 예시 결과 `DEMO_RESULT`, 띠 메타 `ZODIAC`).

## Fidelity
**High-fidelity.** 색, 타이포, 간격, 인터랙션, 카피가 모두 최종안이다. 카피(한국어 문구)는 그대로 사용한다.

## 아키텍처 원칙 (중요)
1. **실제 계산.** `saju-data.js`의 `analyze()` 흐름:
   - (a) **만세력**: 무료 오픈소스 `lunar-javascript`(CDN)로 사주팔자를 계산한다. 입춘·절기 기준이고, 음력/윤달 변환과 대운(성별 입력 시)을 포함한다. 대한민국 출생 시각 보정은 `koreaCorrection()`이 담당한다. 표준시 변경 이력을 반영해 UTC+9 시기는 −30분, 1908-04-01~1911-12-31과 1954-03-21~1961-08-10의 UTC+8:30 시기는 0분을 적용한다. 서머타임 12개 기간(1948–51, 1955–60, 1987–88, 시작·종료 시각 포함)은 −60분을 자동 적용한다. 자시 처리는 국내 만세력 일반 기준을 따른다. 보정 후 태양시 23시부터 일주를 다음 날로 바꾸고 야자시는 적용하지 않는다(`ec.setSect(1)`). **년·월주와 대운은 실제 절입 순간으로 판정한다.** 라이브러리 절기표가 UTC+8 기준이라, 출생 시각을 UTC+8로 환산한 순간(`ecInst`)으로 계산한다. 일·시주는 태양시 기준(`ec`)으로 계산한다. 음력→양력 변환은 **KASI 음양력 데이터 기반 공개 라이브러리 `korean-lunar-calendar@0.4.0`(CDN, 1000–2050년)**을 우선 사용한다. 범위 밖이거나 로드에 실패하면 자체 계산(`krLunarMonths`)으로 대체한다. 자체 계산은 1900–2027년 46,747일 대조에서 11개월(1903–1911년 8건, 1914·1916·1920년 삭이 자정 몇 분 전후인 3건)이 하루씩 어긋나 기본값에서 제외했다. 실제 사용 경로는 1900–2027년 15,574일을 표본 대조해 불일치 0건이었다. 그 전에 자체 계산 시절에 확인한 내용: 1900–2031년 윤달 132년이 공개 윤달표와 모두 일치했고, 2033년 윤11월(12/22)도 맞았다. 삭·중기 순간을 KST 날짜로 옮긴 뒤, 동지가 든 달을 11월로 두고 13개월인 해에는 중기 없는 첫 달을 윤달로 정한다. 이렇게 달 시작과 윤달을 모두 새로 정한다. 1900–2050년 검증에서 중국과 윤달이 다른 해는 2012년(한 윤3월 / 중 윤4월)과 2017년(한 윤5월 / 중 윤6월)이었고, 둘 다 한국천문연구원 음력과 일치한다. 설날이 다른 해는 8개였다(예: 1997년 2/8, 2027년 2/7). 시간 모름이면 시주를 비우고 6글자로 센다. 십신은 자체 계산(지지는 본기 기준)한다.
   - (b) **띠 궁합**: 년지 기준 육합(1위)·삼합(2·3위)을 규칙으로 계산한다. 2027 정미년은 未와의 합충 점수 + 내 띠와의 합충 점수로 정렬한다.
   - (c) **해석 문장**: 계산된 명식을 프롬프트로 LLM(프로토타입에서는 `window.claude.complete`, haiku)이 JSON으로 작성한다. 금지 규칙(점수·확률·단정·투자 추천 등)이 프롬프트에 들어 있다. 실패하면 계산 결과만 보여 주고 ‘해석 다시 불러오기’를 띄운다. 성공한 결과만 캐시해서, 같은 입력에는 같은 결과를 보여 준다.
   - 실서비스에서는 (c)를 서버 측 LLM 호출로 옮기고, 결과를 입력 해시로 캐시한다.
2. **세 계층 분리:** 입력 폼 상태 → `toInput()`로 정규화한 요청 객체 → `analyze(input)` → 결과 객체 → 화면 렌더.
3. **점수·확률 금지.** 키워드와 설명으로만 전달한다. 오행은 8글자 중 등장 개수이며 점수가 아니다.

### 입력 계약 (`toInput` 결과)
```ts
{ name: string|null; calendar: 'solar'|'lunar'; isLeapMonth: boolean;
  birth: { year: number; month: number; day: number };
  time: { hour: number; minute: number } | null;   // null = 시간 모름
  region: string;                                   // 기본 '대한민국'
  gender: 'female'|'male'|null }                   // 대운 순·역행 계산용, 선택
```

- `type:'fortune'` → `title, icon(한자), summary, body[3–5], tips[], details[{label,text}]`
- `type:'match'` → `ranks[3]{rank,animal,keywords[],relation,reason}`, `notice`, `boundary`
- `type:'year'` → `ranks[3]{rank,animal,activity,expect,caution}`, `criteria`

## 결과 이미지 저장
- 화면 밖에 540×675 공유 카드를 렌더한다(로고, 데모 배지, 제목, 입력 정보, 요약, 키워드, 어울리는 띠 TOP3, 면책 문구). `html-to-image`의 `toBlob(pixelRatio 2)`로 1080×1350 PNG를 만든다. 폰트 임베드에 실패하면 `skipFonts`로 다시 시도한다.
- 터치 기기에서 `navigator.canShare({files})`가 되면 Web Share 시트를 띄우고, 아니면 `<a download="운결_{이름}.png">`로 다운로드한다. 버튼 상태는 "이미지 만드는 중…"이며, 결과 메시지를 aria-live로 알린다.
- 이미지는 기기에서만 만들어지고 업로드되지 않는다(안내 문구 있음). 실제 결과가 연결되기 전에는 카드에 데모 배지가 반드시 들어가야 한다.

## Validation
- 연: 필수, 4자리, 1900 이상, 올해 이하. 월: 1–12. 일: 양력은 해당 월 말일까지(윤년 반영), 음력은 1–30. 오늘 이후 날짜는 오류로 처리한다.
- 시간 모름이 아니면 시는 필수(0–23), 분은 선택(0–59). 지역이 기타면 직접 입력이 필수다.
- 오류는 blur한 필드, 또는 제출 시도 후 전체에 표시한다(`#A33A2A`, 테두리 동일). 제출할 때 첫 오류 필드로 포커스를 옮긴다. 메시지는 aria-live로 알린다.
- 숫자 입력: 한글 IME 조합 중에는 걸러 내지 않고, 조합이 끝나면 전각 숫자를 일반 숫자로 바꾼 뒤 숫자만 남긴다. blur 시 한 번 더 정리한다.
